这是一个项目实践，旨在通过java控制数据库进行查询以及DML操作



# 分层设计

1. **App** 展示菜单，接收数据，并调用相关的Service类，完成对应功能
2. **Service** 业务层，进行数据处理，由App调用，返回给App处理后的数据
3. **DAO** DAO，连接java和数据库的连接池等技术
4. **Utils** 此类作为工具类，存放DAO相关工具



# 登录菜单

思路：登录菜单为app层，此层不做数据处理，只做数据的传入，传出，与判断，将菜单包装成方法，loop控制菜单，将菜单作为传入数据的窗口，用来将参数传给业务层，需要完成显示菜单和其功能的作用。

登录：将用户传入的参数，用DAO在Service层中新建方法login，用于验证用户名的账户密码是否正确





# 预订座位

思路：要预定座位有两个要考虑的因素

1. 用户传入的编号是否存在
2. 此编号是否已经是已预定状态





# 菜品菜单

思路：很简单，写一个Service方法封装了全表查询，再在App里封装一个showMenu的方法，在App循环菜单中调用方法



# 点餐



## Bill表

| 字段名     | 类型     | 长度 | 小数点 | 不是 null | 虚拟 | 键   | 注释                                        |
| ---------- | -------- | ---- | ------ | --------- | ---- | ---- | ------------------------------------------- |
| bid        | int      | 0    | 0      | ☑         | ☐    | 主键 | 账单ID，自增                                |
| tid        | int      | 0    | 0      | ☑         | ☐    |      | 餐桌编号（来自 table_status.tid，逻辑外键） |
| mid        | int      | 0    | 0      | ☑         | ☐    |      | 菜品编号（来自 menu.mid，逻辑外键）         |
| nums       | int      | 0    | 0      | ☑         | ☐    |      | 菜品数量                                    |
| cost       | decimal  | 10   | 2      | ☑         | ☐    |      | 金额 = menu.price × nums                    |
| payMethod  | varchar  | 20   | 0      | ☑         | ☐    |      | 现金/微信/支付宝等，结账时填写，点餐时为空  |
| createTime | datetime | 0    | 0      | ☑         | ☐    |      | 下单时间，插入时自动记录当前时间            |





功能说明：要求对 **餐桌号** **菜品编号** 做合理性校验，如果不合理，给出提示信息

1. **餐桌号**合理校验：不能在预定为null的餐桌点餐

   用Check方法进行校验

2. **菜品编号**合理校验：不能点菜单上没有的菜

   按照id查询后返回值为null的即为菜单上没有的菜

3. 点餐成功需要修改餐桌状态

4. 生成账单（bills）



思路：

用户进入点餐菜单，选择桌号，菜品编号，菜品数量，确认点菜，返回点餐结果1或0判断点餐成功与否
